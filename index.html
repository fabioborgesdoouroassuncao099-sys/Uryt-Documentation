URYT

Documentação oficial · v0.1

A Uryt é uma linguagem de programação compilada, de extensão .Uryt, criada com foco em aplicações visuais, imagens e jogos. Sua proposta é oferecer uma sintaxe curta, original e independente, sem copiar estruturas de linguagens consagradas como Python, JavaScript ou C. Cada comando tem nome e forma próprios, o que dá à linguagem identidade clara e distinta de qualquer outra existente.

A estrutura de um arquivo Uryt consiste em uma sequência de comandos escritos linha a linha. O ponto e vírgula atua como separador de comandos, mas só aparece ao final de uma linha quando existe mais código depois dela. Se o comando for o último do arquivo, ele termina sem ponto e vírgula. Essa regra vale para todos os comandos da linguagem, incluindo os comandos de imagem.

Comentários são escritos entre colchetes. Tudo o que estiver entre um colchete de abertura e um de fechamento é ignorado pelo compilador. Essa é a única forma de comentário na linguagem, e ela serve tanto para anotações do programador quanto para documentar trechos do código.

O operador central da Uryt é o /^, que possui dois significados dependendo do contexto. Fora de uma estrutura condicional, ele realiza atribuição, definindo o valor de uma variável. Dentro de uma estrutura condicional, ele realiza comparação de igualdade, testando se dois valores são iguais. Essa polivalência é uma das marcas registradas da linguagem, que resolve a distinção pelo contexto em vez de usar símbolos diferentes.

As variáveis armazenam valores e podem ser usadas em atribuições, comparações e outras operações. A atribuição aceita tanto um número direto quanto o valor de outra variável. Não há necessidade de declarar tipo previamente: a variável assume o valor que lhe for atribuído.

A impressão na tela é feita por meio do comando One.class<text>, seguido do texto entre aspas. Esse comando já imprime diretamente, sem necessidade de chamada adicional. É o principal meio de saída de texto da linguagem.

A estrutura condicional é aberta pelo comando Gl., que recebe uma comparação feita com /^ e termina com ponto e vírgula. O bloco seguinte é executado caso a condição seja verdadeira. O comando Jin; marca o senão, e o bloco posterior a ele é executado caso a condição seja falsa.

O loop é aberto pelo comando L.loop;, que inicia uma estrutura de repetição. O bloco seguinte é repetido enquanto o loop estiver ativo. O modo de encerramento do loop ainda não foi definido formalmente na linguagem.

A Uryt possui suporte nativo a imagens, ou seja, o recurso faz parte da própria linguagem e não de uma biblioteca externa. O único formato aceito é o .jpg. A imagem é carregada pelo comando jpg. seguido do link entre aspas, sem qualquer outro texto dentro das aspas. Após o carregamento, é obrigatório definir o tamanho da imagem por meio dos comandos Rig., Lef., Up. e Down., que correspondem, respectivamente, a direita, esquerda, cima e baixo. Cada comando recebe um número entre parênteses que representa o tamanho. Se o tamanho não for definido, a imagem não aparece. Os comandos de tamanho seguem a mesma regra do ponto e vírgula: ele só aparece ao final se houver mais código depois.

A linguagem é compilada, o que significa que o código-fonte é traduzido antes da execução, e não interpretado linha a linha. Isso dá à Uryt um caráter mais sério e mais próximo de linguagens de baixo nível, ainda que sua sintaxe seja curta e visual.

Diversos pontos da linguagem ainda não foram definidos formalmente. Entre eles estão: a forma de encerramento do loop, a existência de outros operadores de comparação além da igualdade, a presença de operadores aritméticos, a possibilidade de armazenar textos em variáveis, a existência de outros tipos de dados além de número e texto, a forma de leitura de entrada do usuário, a geração de valores aleatórios, o comando de saída do programa e o modo exato como os comandos de tamanho afetam a imagem na prática.

Mesmo com essas definições em aberto, a Uryt já possui identidade consolidada, com sintaxe própria, regras próprias e foco próprio. É uma linguagem pensada para quem quer programar com foco visual, com comandos curtos e com uma estética que remete a sistemas compilados de verdade.

Uryt is a compiled programming language, with the .Uryt extension, created with a focus on visual applications, images, and games. Its aim is to offer a short, original, and independent syntax, without copying structures from established languages like Python, JavaScript, or C. Each command has its own name and form, giving the language a clear and distinct identity from any other.

The structure of a Uryt file consists of a sequence of commands written line by line. The semicolon acts as a command separator, but only appears at the end of a line when there is more code after it. If the command is the last in the file, it ends without a semicolon. This rule applies to all commands in the language, including image commands.

Comments are written between square brackets. Everything between an opening and closing square bracket is ignored by the compiler. This is the only form of comment in the language, and it serves both for programmer notes and for documenting sections of code.

The central operator of Uryt is /^, which has two meanings depending on the context. Outside of a conditional structure, it performs assignment, setting the value of a variable. Inside a conditional structure, it performs equality comparison, testing if two values are equal. This versatility is one of the hallmarks of the language, which resolves the distinction through context instead of using different symbols.

Variables store values and can be used in assignments, comparisons, and other operations. Assignment accepts both a direct number and the value of another variable. There is no need to declare the type beforehand: the variable assumes the value assigned to it.

Printing to the screen is done using the One.class<text> command, followed by the text in quotation marks. This command prints directly, without needing an additional call. It's the language's main way of outputting text.

The conditional structure is opened by the Gl. command, which receives a comparison made with /^ and ends with a semicolon. The following block is executed if the condition is true. The Jin; command marks the else, and the block after it is executed if the condition is false.

The loop is opened by the L.loop; command, which starts a repetition structure. The following block is repeated while the loop is active. The loop termination method has not yet been formally defined in the language.

Uryt has native image support; that is, the feature is part of the language itself and not an external library. The only accepted format is .jpg. The image is loaded by the jpg. command followed by the link in quotation marks, without any other text inside the quotation marks. After loading, it is mandatory to define the image size using the Rig., Lef., Up., and Down. commands, which correspond to right, left, up, and down, respectively. Each command receives a number in parentheses representing the size. If the size is not defined, the image does not appear. Size commands follow the same rule as the semicolon: it only appears at the end if there is more code after it.

The language is compiled, meaning that the source code is translated before execution, not interpreted line by line. This gives Uryt a more serious character and makes it closer to low-level languages, even though its syntax is short and visual.

Several aspects of the language have not yet been formally defined. Among them are: the way the loop ends, the existence of other comparison operators besides equality, the presence of arithmetic operators, the possibility of storing text in variables, the existence of other data types besides numbers and text, the way user input is read, the generation of random values, the program's exit command, and the exact way in which size commands affect the image in practice.

Even with these open definitions, Uryt already has a consolidated identity, with its own syntax, rules, and focus. It's a language designed for those who want to program with a visual focus, using short commands and with an aesthetic reminiscent of real compiled systems.
